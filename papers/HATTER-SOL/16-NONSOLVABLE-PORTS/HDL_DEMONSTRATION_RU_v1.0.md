# HATTER-SOL-16 · Контрольная демонстрационная работа на Verilog

## Реализация пятипробового декодера орбит PSL(2,7)

**Статус:** демонстрационная / контрольная работа к HATTER-SOL-16  
**Дата:** 16.09.2026  
**Платформа моделирования:** EDA Playground  
**Публичный playground:** https://www.edaplayground.com/x/Z4Bx  
**Назначение:** аппаратная проверка того, что математически доказанная в H16 пятипробовая сигнатура естественно реализуется как компактный синхронный цифровой тракт.

---

## 1. Цель работы

В HATTER-SOL-16 доказано, что для всех 114 орбит порождающих пар группы `PSL(2,7)` относительно одновременного сопряжения достаточно пяти ориентированных следовых проб

\[
A,\qquad B,\qquad AB,\qquad AB^{-1},\qquad K=[A,B],
\]

причём максимальная глубина слова равна четырём. Цель этой работы — не реализовать всю математику группы в HDL, а проверить аппаратную форму уже доказанного интерфейса:

\[
\boxed{
\text{5 классовых входов}
\rightarrow
\text{15-битная сигнатура}
\rightarrow
Q_4\text{-ориентация}
\rightarrow
\text{LUT/ROM}
\rightarrow
\text{orbit ID}.
}
\]

Это именно контрольная демонстрация H16. Полный 114-строчный ROM, автоматическая генерация golden vectors, fixed-point representation channel, синтез и работа на реальной FPGA относятся к HATTER-SOL-17.

---

## 2. Входные данные и кодирование

Каждый из пяти наблюдаемых групповых элементов сначала сводится к одному из шести классов сопряжённости `PSL(2,7)`:

| Класс | 3-битный код |
|---|---|
| `1A` | `000` |
| `2A` | `001` |
| `3A` | `010` |
| `4A` | `011` |
| `7A` | `100` |
| `7B` | `101` |

Пять трёхбитных значений объединяются в один 15-битный вектор

\[
\boxed{
\texttt{signature}=
\{\texttt{class\_A},\texttt{class\_B},\texttt{class\_AB},
\texttt{class\_AB\_inv},\texttt{class\_K}\}.
}
\]

В демонстрационной схеме это уже готовый цифровой интерфейс. То есть HDL-блок не вычисляет классы из матриц представления — он проверяет следующую ступень архитектуры: упаковку, ориентационный канал и декодирование орбиты.

---

## 3. Извлечение ориентации Q4

Для коммутатора

\[
K=[A,B]
\]

в H16 доказан точный ориентационный наблюдатель

\[
Q_4(A,B)=
\frac{\operatorname{Tr}\rho_3(K)-\operatorname{Tr}\rho_3(K^{-1})}{i\sqrt7}.
\]

На классовом уровне он принимает значения

\[
Q_4=0\quad\text{для }3A,4A,
\]

\[
Q_4=+1\quad\text{для }7A,
\qquad
Q_4=-1\quad\text{для }7B.
\]

В RTL это сводится к простому комбинационному декодеру:

```verilog
assign q4_next = (class_K == 3'd4) ? 2'b01 : // 7A -> +1
                 (class_K == 3'd5) ? 2'b10 : // 7B -> -1
                                     2'b00;  // other classes -> 0
```

Использовано кодирование состояний

\[
0\mapsto00,
\qquad
+1\mapsto01,
\qquad
-1\mapsto10.
\]

Таким образом, математически нетривиальная ориентационная информация после классового распознавания превращается в очень дешёвую цифровую операцию.

---

## 4. Декодирование орбиты

Поскольку теорема H16 утверждает инъективность пятипробовой сигнатуры на 114 орбитах, аппаратный декодер может быть конечным LUT/ROM:

```verilog
always @(*) begin
    case (signature)
        15'b011_011_010_011_100: lut_orbit = 7'd42;
        15'b011_011_010_011_101: lut_orbit = 7'd43;
        default:                  lut_orbit = 7'h7F;
    endcase
end
```

В контрольной работе реализованы только две демонстрационные строки. Номера `42` и `43` являются тестовыми идентификаторами, а не ещё замороженной канонической нумерацией всех 114 орбит.

Значение

```text
7'h7F = 127
```

используется как `UNKNOWN` для сигнатур, отсутствующих в демонстрационном LUT.

## 5. Синхронный тракт

Выходы регистрируются по положительному фронту `clk`:

```verilog
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        valid_out      <= 1'b0;
        q4_orientation <= 2'b00;
        orbit_id       <= 7'd0;
    end else begin
        valid_out      <= valid_in;
        q4_orientation <= q4_next;
        orbit_id       <= lut_orbit;
    end
end
```

Это даёт простую одноступенчатую конвейерную архитектуру:

\[
\text{inputs}
\rightarrow
\text{combinational signature/Q4/LUT}
\rightarrow
\text{registered output}.
\]

Такой интерфейс уже близок к обычной FPGA-реализации и не требует сложной управляющей логики на этом уровне.

## 6. Testbench и контрольные векторы

Проверяются два вектора, отличающиеся только классом коммутатора:

### Golden Vector 1

```text
class_A      = 011 = 4A
class_B      = 011 = 4A
class_AB     = 010 = 3A
class_AB_inv = 011 = 4A
class_K      = 100 = 7A
```

Отсюда

```text
signature = 011_011_010_011_100
Q4        = +1 = 01
orbit_id  = 42
```

### Golden Vector 2

```text
class_A      = 011 = 4A
class_B      = 011 = 4A
class_AB     = 010 = 3A
class_AB_inv = 011 = 4A
class_K      = 101 = 7B
```

Отсюда

```text
signature = 011_011_010_011_101
Q4        = -1 = 10
orbit_id  = 43
```

Особенно важно, что первые четыре компонента совпадают, а изменение `7A -> 7B` только в коммутаторном канале меняет и состояние ориентации, и декодированную строку LUT. Это наглядно показывает, зачем H16 понадобился ориентированный, а не только вещественный скалярный наблюдатель.

## 7. Результат моделирования

Осциллограмма EDA Playground показывает ожидаемую последовательность:

1. после сброса выходы находятся в нуле;
2. первый валидный вектор захватывается в синхронный выход и формирует `Q4=01`, `orbit_id=42`;
3. второй вектор формирует `Q4=10`, `orbit_id=43`;
4. `valid_out` повторяет `valid_in` с регистровой синхронизацией;
5. неизвестное значение в демонстрационном LUT кодируется `7'h7F`.

Публичный стенд:

https://www.edaplayground.com/x/Z4Bx

По представленной пользователем осциллограмме переходы `class_K=4 -> 5`, `q4_orientation=1 -> 2` и `orbit_id=2a -> 2b` согласуются с RTL-описанием.

## 8. Как воспроизвести

### В EDA Playground

Открыть публичный playground, выбрать Verilog/SystemVerilog simulator, выполнить `Run`, затем открыть `EPWave` для `dump.vcd`.

Страница shared playground может быть просмотрена по публичной ссылке. Сам EDA Playground указывает, что для запуска симуляторов пользователю требуется вход в систему; это ограничение сервиса, а не HDL-кода.

### Локально из терминала с Icarus Verilog

Тот же тест не зависит от EDA Playground и может быть запущен обычным способом:

```bash
iverilog -g2012 -o h16_sim \
  h16_orbit_decoder.v tb_h16_orbit_decoder.v
vvp h16_sim
```

Файл `dump.vcd` затем можно открыть, например, в GTKWave:

```bash
gtkwave dump.vcd
```

Таким образом, «запуск из терминала» для опубликованного HDL полностью воспроизводим без веб-сервиса.

## 9. Практическая значимость

Эта контрольная работа переводит основной теоретический результат H16 в стандартную цифровую архитектуру. Она показывает, что после классового распознавания:

- пять математических проб требуют всего `15` входных бит;
- ориентационный канал `Q4` реализуется простой комбинационной логикой;
- идентификатор одной из 114 орбит помещается в `7` бит;
- декодирование естественно реализуется LUT/ROM;
- весь блок может быть оформлен как одноступенчатый синхронный pipeline.

Главная практическая ценность состоит не в двух тестовых строках ROM, а в том, что между доказанной конечной томографией и обычной FPGA-структурой **нет архитектурного разрыва**.

Математика H16 задаёт точный информационный интерфейс, а RTL показывает его прямую реализуемость.

---

## 10. Выводы

Контрольная работа подтверждает аппаратную состоятельность frozen specification H16 на уровне RTL proof-of-concept.

Получен тракт

\[
\boxed{
5\times3\text{ bit class inputs}
\rightarrow15\text{ bit signature}
\rightarrow2\text{ bit }Q_4
\rightarrow7\text{ bit orbit ID}.
}
\]

Два golden vectors демонстрируют принципиально важный случай `7A/7B`: одинаковые первые четыре пробы и противоположная ориентация коммутатора приводят к различимым аппаратным состояниям.

Этого достаточно для HATTER-SOL-16 как демонстрации инженерной реализуемости математического результата. Следующая ступень HATTER-SOL-17 должна автоматически построить полный 114-entry ROM из точного математического сертификата, проверить все golden vectors, оценить ресурсы и тайминги после synthesis и перенести блок на физическую FPGA.
