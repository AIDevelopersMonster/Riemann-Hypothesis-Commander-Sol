# Учебный курс H17-LAB-01

## Цель

Этот каталог превращает H17-LAB-01 из набора RTL-файлов в полноценный учебный стенд: от интуитивной идеи восстановления потерянной информации до конечной группы, RTL-автомата, UART-протокола и архитектурного исследования.

Главная идея:

~~~text
8 связанных математических признаков
        |
        | теряем один известный признак
        v
7 оставшихся признаков
        |
        | математическая структура
        v
восстановленный восьмой признак
~~~

Здесь не хранится резервная копия потерянного 3-битного поля. В LAB-01 восстановление выполняется поиском единственной generating-orbit signature, совместимой с семью сохранившимися координатами.

## Четыре уровня объяснения

| Уровень | Требования | Смысл |
|---|---|---|
| A — наглядный | школьная информатика | 8 признаков, один потеряли, 7 восстановили |
| B — инженерный | основы цифровой техники | кодирование, FSM, latency, UART, testbench |
| C — математический | группы/дискретная математика | PSL(2,7), сопряжение, орбиты, fingerprint |
| D — исследовательский | HDL + алгебра | robust code, distance, architecture trade-offs |

Теория: THEORY_LEVELS_RU.md.

Инженерная:

Полная:

LAB-00 -> LAB-01 -> LAB-02 -> LAB-03 -> LAB-04 -> LAB-05 -> LAB-06 -> LAB-07
~~~

## Работы

| Работа | Тема | Время |
|---|---|---:|
| LAB-00 | Развёртывание и первый PASS | 30–60 мин |
| LAB-01 | Перестановки и 24-битное представление | 60–90 мин |
| LAB-02 | Восемь probes и fingerprint | 60–90 мин |
| LAB-03 | Известное стирание и восстановление 1 из 8 | 90 мин |
| LAB-04 | FSM, 1663 такта и waveform | 90–120 мин |
| LAB-05 | UART, CRC и ошибки протокола | 90–120 мин |
| LAB-06 | Verilog/VHDL как независимые реализации | 90 мин |
| LAB-07 | Площадь против latency | 2–4 ч |

## ПО

Для LAB-00…05 на Windows 10 достаточно Git, Python 3, Icarus Verilog и PowerShell. GTKWave нужен для удобного просмотра LAB-04. GHDL нужен только для LAB-06.

Физическая FPGA для базового курса не требуется.

## Главное правило

В любом отчёте разделять:

1. математическое утверждение;
2. результат RTL-симуляции;
3. утверждение о физической FPGA.

PASS симуляции не даёт автоматически LUT, Fmax, power или подтверждение работы на реальной плате.
