H17-LAB-01 — лабораторный комплект для FPGA
=============================================

Назначение
----------
Это опорный последовательный процессор H17. Он принимает две перестановки
A и B (по 24 бита: восемь 3-битных значений), проверяет их принадлежность
PSL(2,7), вычисляет восемь проб, моделирует известное стирание одной пробы
и возвращает статус, номер орбиты и три fingerprint-значения.

В пакет включены оба языка HDL:
  rtl/verilog/h17_core.v       — ядро Verilog
  rtl/verilog/h17_tables.vh    — таблицы PSL(2,7), орбит и проб для Verilog
  rtl/vhdl/h17_core.vhd        — ядро VHDL
  rtl/vhdl/h17_tables.vhd      — package h17_tables для VHDL
  rtl/*/h17_uart*              — UART-интерфейс и верхний модуль
  tb/                          — testbench для ядра и UART
  vectors/quick.txt            — 1 796 коротких точных тест-векторов
  vectors/full.txt             — 29 911 полных тест-векторов
  vectors/format.json          — точный формат строк векторов
  board/                       — шаблон проекта Arty A7-35 и XDC
  tools/host.py                — обмен ПК ↔ FPGA через USB-UART

Важно: этот архив содержит исходники и векторы. Он не содержит bitstream
и не является отчётом о пройденной симуляции/синтезе.

Формат входа
------------
Ядро принимает:
  clk, rst, start;
  a_in[23:0], b_in[23:0];
  mode_in[3:0].

mode_in=0 означает отсутствие стирания. Значения 1..8 означают известное
стирание соответствующего поля из восьми 3-битных полей. mode_in>8 — ошибка
режима. После импульса start дождаться done=1; busy=1 показывает обработку.

Результаты
----------
  status=0  idle/reset ИЛИ завершённый запрос с A/B вне PSL(2,7);
  status=1  восстановление не найдено;
  status=2  найдено ровно одно восстановление (успех);
  status=3  найдено несколько восстановлений;
  status=4  недопустимый mode_in.

orbit_id=127 используется как недействительный идентификатор.
raw_signature — восемь исходных 3-битных классов;
observed_signature — fingerprint после стирания;
repaired_signature — однозначно восстановленный fingerprint.

Как проверять локально (только по отдельному решению)
------------------------------------------------------
Ничего из этих команд не запускалось при сборке архива.

  make test-verilog VECTORS=vectors/quick.txt
  make test-vhdl    VECTORS=vectors/quick.txt

Полный набор: заменить quick.txt на full.txt. Перед запуском нужны Icarus
Verilog (iverilog/vvp) для Verilog и GHDL для VHDL. Тестбенчи читают строки
из vectors/*.txt и сопоставляют выходы с golden-значениями каждой строки.

Проверка на реальной плате
--------------------------
Минимальный стенд: Digilent Arty A7-35, USB-кабель данных, ПК. Выбор Arty
здесь — готовый шаблон, а не утверждение, что именно эта плата уже проверена.

1. Собрать один вариант верхнего модуля (Verilog или VHDL), применив
   board/arty_a7_35.xdc и board/build_vivado.tcl как исходную основу.
2. Подать clock/reset в соответствии с платой; подключить USB-UART платы.
3. С ПК передавать векторы программой tools/host.py; сначала demo.txt,
   затем quick.txt.
4. Для каждой операции сравнивать status, orbit_id и три signatures с
   колонками той же строки вектора. Это проверяет интерфейс, перенос данных,
   вычисление проб и восстановление после известного стирания.
5. Отдельно снять отчёты utilization и timing. Только после этого можно
   утверждать пригодность выбранной FPGA и выбирать closure-flat либо
   ROM-free для следующего аппаратного этапа.

Границы
-------
Этот H17-LAB-01 — понятный reference-процессор для лаборатории, не прямой
проект H17-08 closure-flat/ROM-free. Он нужен, чтобы сначала зафиксировать
протокол ввода/вывода и golden-векторы на реальном железе.
