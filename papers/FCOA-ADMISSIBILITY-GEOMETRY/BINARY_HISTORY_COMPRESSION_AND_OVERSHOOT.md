# Binary-History Compression and Arithmetic Overshoot

**Project:** FCOA Admissibility Geometry  
**Status:** central theorem candidate / compression checkpoint  
**Scope:** generated history materialization after the Regular-Primitive Barrier

## 1. Target

The previous central result showed that finite-copy position-regular primitive operations cannot first-order recover EqGap. Therefore any successful static FO materialization of synchronized displacement must put nonregular information somewhere in the primitive structure.

The next question is quantitative:

\[
\boxed{
\text{Can the missing history be materialized with }o(m^2)\text{ support?}
}
\]

where

\[
m=|G_N|=N-1.
\]

The answer is **yes**.

A binary-counter history generated by a fixed local carry process produces only

\[
\Theta(m\log m)
\]

materialized bit/history incidences, yet ordinary first-order logic can reconstruct truncated addition from them.

However the compression overshoots the additive gateway: the resulting BIT structure has the full finite-arithmetic first-order strength classically known as

\[
FO(BIT)=FO(PLUS,TIMES).
\]

Thus subquadratic AL1 exposure is possible, but this simplest binary history is too strong if the goal is a clean additive-only layer.

## 2. Generated binary history, not an external rank table

Use the recovered generic chain

\[
G_m=\{g_0<g_1<\cdots<g_{m-1}\}.
\]

The subscripts are metamathematical labels only.

We generate a relation

\[
B(x,i),
\]

where the second coordinate is another generic point used as a digit-position coordinate.

The generator is a prefix-consistent binary counter.

### Local counter protocol

At the least generic point, all bits are zero.

When the next carrier point \(x'=\operatorname{Succ}(x)\) is created, a carry head starts at the least digit position in state `CARRY`.

At digit position \(i\):

1. if the previous row has bit `0` at \(i\), write `1` in the new row, switch to `COPY`, and advance;
2. if the previous row has bit `1` at \(i\), write `0` in the new row and advance while staying in `CARRY`;
3. in `COPY`, copy the remaining old bits one position at a time;
4. if carry exits the current highest active digit, activate the next digit position and write `1` there.

The control set is finite. The rule uses only:

- successor on the number coordinate;
- successor on the digit coordinate;
- the previous row's local bit value;
- finitely many control states.

It never queries the final carrier size \(m\), a numerical rank, addition, EqGap, multiplication, or an external unary arithmetic function.

Extending the carrier continues the same counter and never changes previously generated bit facts.

This is therefore generated leakage under the Uniformity Firewall, not a size oracle.

## 3. Correctness of the counter history

### Proposition 3.1

After the row for \(g_n\) is generated,

\[
B(g_n,g_j)
\]

holds exactly when the \(j\)-th binary digit of \(n\) is `1`.

### Proof

Induct on \(n\).

The least row represents zero. The local update rule is exactly the ordinary carry rule for incrementing a binary word by one: consecutive low `1` bits become `0`, the first `0` becomes `1`, and all higher bits are copied unchanged. Hence the new row represents \(n+1\). \(\square\)

The proposition is only an external correctness proof. The final signature contains the relation \(B\), not the numerical rank function.

## 4. Explicit history-sort realization

If one wants every generated memory cell to be an explicit FCOA-style object, introduce history objects

\[
h_{x,i}
\]

only for digit positions active when row \(x\) is produced.

Use incidence relations

\[
\operatorname{Row}(h,x),
\qquad
\operatorname{Pos}(h,i),
\qquad
\operatorname{One}(h).
\]

Then

\[
B(x,i)
\iff
\exists h\,[
\operatorname{Row}(h,x)
\land
\operatorname{Pos}(h,i)
\land
\operatorname{One}(h)
].
\]

Missing old high-digit cells mean zero. New digit positions are created only on overflow.

Thus the binary relation presentation and the explicit history-sort presentation are FO-equivalent for the purpose of reading the stored bits.

The latter makes the closure placement completely visible: the unbounded traversal has been materialized as a growing two-dimensional history layer.

## 5. Support count

Let

\[
s_2(n)
\]

denote the number of `1` bits in the binary expansion of \(n\). Then the number of positive bit incidences on the first \(m\) rows is

\[
S_B(m)
=
\sum_{n=0}^{m-1}s_2(n).
\]

For each bit position \(j<\lceil\log_2m\rceil\), that bit is `1` on alternating blocks of length \(2^j\). Its number of occurrences among the first \(m\) rows is

\[
\frac m2+O(2^j).
\]

Summing over all active positions gives

\[
S_B(m)
=
\frac12m\log_2m+O(m).
\]

Hence

\[
\boxed{
S_B(m)=\Theta(m\log m)=o(m^2).
}
\]

In the explicit history-sort version, storing both zero and one cells still uses only

\[
\Theta(m\log m)
\]

history objects and \(O(1)\) incidences per object.

Thus the result is not an artifact of counting only the positive BIT relation.

## 6. Carry is first-order definable from BIT

We now forget the generation process and work in the static expansion

\[
(G_m,<,B).
\]

Define the carry into digit position \(i\) for numbers \(x,y\) by

\[
\operatorname{Carry}(x,y,i)
\]

iff there exists a lower digit \(j<i\) such that both inputs have `1` at \(j\), and every intermediate digit propagates a carry:

\[
\exists j\Bigl[
 j<i
 \land B(x,j)
 \land B(y,j)
 \land
 \forall k\bigl(
 j<k<i
 \rightarrow
 (B(x,k)\lor B(y,k))
 \bigr)
\Bigr].
\]

This is the standard generate/propagate characterization of binary carry.

At the least digit there is no carry because no lower witness \(j\) exists.

## 7. Uniform FO definition of truncated addition

Let

\[
XOR_3(p,q,r)
\]

be the fixed Boolean formula saying that an odd number of \(p,q,r\) are true.

Define

\[
\operatorname{Add}_B(x,y,z)
\]

by

\[
\forall i\;
\Bigl(
B(z,i)
\leftrightarrow
XOR_3(
B(x,i),
B(y,i),
\operatorname{Carry}(x,y,i)
)
\Bigr).
\]

### Theorem 7.1 — Binary-History Addition Theorem

For every \(m\ge2\),

\[
\boxed{
\operatorname{Add}_B(x,y,z)
\iff
\operatorname{rk}(z)
=
\operatorname{rk}(x)+\operatorname{rk}(y)<m.
}
\]

### Proof

By Proposition 3.1, \(B(x,i)\) gives the binary digits of the external rank of \(x\). Section 6 gives exactly the incoming carry at every bit position. The XOR condition is therefore the ordinary binary sum rule.

The quantifier over digit positions ranges over all \(G_m\). This is more than enough to see every bit of a sum of two numbers below \(m\), since the highest possible sum is \(2m-2\) and its highest bit position is strictly below \(m\) for \(m\ge2\).

Thus no modular wraparound is possible. A target \(z\in G_m\) satisfies the bit equations exactly when its rank is the ordinary sum and that sum is still below \(m\). \(\square\)

Consequently the previously fixed relation

\[
\operatorname{EqGap}
\]

is also uniformly FO-definable from \((<,B)\) through its fixed interdefinition with truncated addition.

## 8. Compression achieved

The generated structure therefore has

\[
\boxed{
\Theta(m\log m)
}
\]

materialized history support and nevertheless exposes a partial operation whose graph contains

\[
\Theta(m^2)
\]

defined input pairs, as well as EqGap with

\[
\Theta(m^3)
\]

true forward-interval quadruples.

This is a genuine static-FO compression effect:

\[
\boxed{
\Theta(m\log m)\text{ stored history}
\Longrightarrow
\Theta(m^2)\text{ additive interaction recovered by FO}.
}
\]

No transitive-closure operator remains in the final query language; the needed traversal history was materialized beforehand.

## 9. Direct interval-code lower bound

The result also explains why a naive history representation stays quadratic.

Suppose a primitive incidence relation

\[
C(a,b,h)
\]

assigns at least one explicit history/length witness \(h\) to every forward interval \((a,b)\), and EqGap is recovered by sharing such a code.

There are

\[
\frac{m(m+1)}2
\]

forward intervals. Therefore even before counting any internal structure on the history objects,

\[
|C|
\ge
\frac{m(m+1)}2
=
\Theta(m^2).
\]

Hence:

\[
\boxed{
\text{one explicit witness incidence per interval cannot yield subquadratic support.}
}
\]

Binary history escapes the bound because it does not attach one code object to each interval. It distributes reusable endpoint information across only \(O(\log m)\) digit features per point and lets FO reconstruct the displacement relation compositionally.

## 10. Arithmetic overshoot

The price of this compression is logical strength.

The relation \(B(x,i)\) is exactly the classical BIT predicate, up to argument order and the external identification of the finite generic chain with an initial segment of the naturals.

A standard theorem of finite model theory gives

\[
\boxed{
FO(BIT)=FO(PLUS,TIMES)
}
\]

over finite initial segments. See Neil Immerman, *Descriptive Complexity*, Springer, 1999, Section 1.2.1 / Theorem 1.17 and the discussion of `FO(BIT)=FO(PLUS,TIMES)`.

Therefore the binary-history structure does not stop at the additive gateway:

\[
\boxed{
\text{Binary History reaches the finite full-arithmetic layer }AL2.
}
\]

This is a calibration statement using a classical theorem, not a novelty claim.

## 11. New tradeoff

We now have two opposite realizations of displacement memory.

### Direct additive materialization

Truncated addition as a primitive partial operation:

\[
|\operatorname{Dom}(+_{\rm trunc})|
=
\Theta(m^2),
\]

with exact AL1 content by construction.

### Distributed binary history

BIT/history support:

\[
\Theta(m\log m),
\]

but classical FO strength jumps to AL2.

Thus compression and leakage are again orthogonal:

\[
\boxed{
\text{better support compression can come with stronger arithmetic overshoot.}
}
\]

This is the sharpest internal example so far of the Density-Leakage Orthogonality principle.

## 12. Closure-Placement interpretation

The construction occupies case (3) of the Closure-Placement Principle.

The local binary-counter generator performs unbounded carry traversal, but instead of asking ordinary FO to recover that traversal dynamically, it stores the resulting history in an auxiliary incidence layer of total size

\[
\Theta(m\log m).
\]

The final BIT relation is non-position-regular, as it must be by the Regular-Primitive Barrier.

Thus:

\[
\boxed{
\text{unbounded closure was not removed; it was compressed into distributed history.}
}
\]

## 13. Generator audit

The construction deliberately separates **specification** from **verification**.

The generator does not say

\[
B(x,i)\iff\text{“the }i\text{-th bit of rank}(x)\text{ is }1”
\]

as its operational rule. That equality is the proved invariant of the locally generated counter.

Operationally the generator uses only finite control plus successor traversal and previously generated bit cells.

Therefore the construction does not import BIT as a table by fiat.

Nevertheless the generator is substantially stronger than U1:

- U1 has finite internal state and one moving carrier coordinate;
- binary history has an unbounded growing digit dimension and local carry traversal across it.

This is exactly the new resource responsible for the escape from the Regular-Primitive Barrier.

## 14. Main negative lesson

The original hope was to materialize synchronized history with subquadratic support and expose equal displacement without importing rank/addition directly.

That hope is achieved:

\[
\boxed{
\Theta(m\log m)=o(m^2)
}
\]

support is enough.

But the most natural compression is **too expressive**:

\[
\boxed{
AL1\text{ is reached and immediately overshot to }AL2.
}
\]

So the difficult problem is no longer whether subquadratic materialization exists.

It does.

The difficult problem is whether it can be **selective**.

## 15. Presburger Compression Corridor

The new exact central target is:

\[
\boxed{
\text{Find a generated history structure with }o(m^2)\text{ support such that}
}
\]

\[
\boxed{
\operatorname{Add}/\operatorname{EqGap}\text{ is uniformly FO-definable,}
}
\]

but

\[
\boxed{
\operatorname{Mul}\text{ is not uniformly FO-definable.}
}
\]

Call this the **Presburger Compression Corridor** as working terminology.

A successful witness would occupy a genuinely compressed AL1 layer between:

\[
\text{regular local memory}
\]

and

\[
\text{BIT/full arithmetic}.
\]

This is now the narrowest central problem.

## 16. Candidate directions

Three routes deserve attack.

1. **Sparse carry-stop / valuation history.** Store only where a binary carry terminates rather than all binary digits. This can have linear support, but it is not yet known whether order plus that history can recover addition.

2. **Dyadic nesting without full BIT exposure.** Materialize a hierarchy of dyadic blocks or predecessor depths while withholding enough endpoint-digit information to prevent recovery of multiplication.

3. **Hybrid additive automaton witnesses.** Materialize local carry certificates sufficient for a fixed addition-checking automaton, but avoid a globally queryable BIT predicate. The challenge is to keep certificate support subquadratic rather than one witness per input pair.

No route is currently promoted.
